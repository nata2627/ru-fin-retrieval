# ru-fin-retrieval

Поисковый слой RAG по нормативным актам Банка России и измерение его качества.

Проект про **измеримое качество поиска**: корпус, набор размеченных запросов,
сравнение конфигураций на одних данных, доверительные интервалы, разбор
провалов. Демонстрационного чат-интерфейса здесь нет и не планируется.

## Состояние

- [x] **Этап 2.** Корпус собран — [docs/02-korpus.md](docs/02-korpus.md)

- [ ] **Этап 5.** Разбор ошибок, блок для резюме

## Что уже есть

**Корпус: 1554 нормативных акта Банка России, 84,4 млн символов, 61 922
фрагмента** — Положения, Инструкции, Указания, Методические рекомендации
и Официальные разъяснения с 2013 по 2026 год.

Главное, что выяснилось по дороге: содержательные акты — Положения,
Инструкции, Указания — выложены на сайте Банка России **сканами
с распознаванием в латинском режиме**. Кириллица подменена похожими
латинскими буквами, и подмена необратима: **И**, **Й** и **Н** сливаются
в одну латинскую `H`. Из выборки в 10 таких файлов пригоден 1.

Те же акты в **«Вестнике Банка России»** набраны в цифре: из выборки
в 10 выпусков пригодны 10, доля кириллицы 99–100%. Корпус строится
из «Вестника», а акты вырезаются из выпусков по началу самого акта.
Проверка нарезки на 25 выпусках: 140 актов из 140, лишних нет.

## Запуск

Нужны Python 3.11+ и `pdftotext` из poppler (`brew install poppler`).

```bash
pip install -r requirements.txt

make probe        # разведка источников (~5 мин)
make corpus       # сбор корпуса: 727 выпусков «Вестника» -> 1554 акта (~25 мин)
make chunks       # нарезка на фрагменты
make bench        # сборка набора запросов и выгрузка в формате MTEB
make metrics      # метрики по выдачам, посчитанным на видеокарте
make errors       # разбор провальных запросов
make latency      # замеры задержки на этой машине
```

`make help` перечисляет все цели.

## Где что считается

Проект развивается на MacBook Air M1 с восемью гигабайтами памяти, и это
определяет архитектуру, а не только расписание. Три операции в неё не
помещаются: инференс языковой модели для генерации запросов, подсчёт
эмбеддингов по 61 922 фрагментам (замерено: bge-m3 даёт 4,9 фрагмента
в секунду на MPS в половинной точности — 3,5 часа на одну модель)
и переранжирование двухсот запросов по пятьдесят кандидатов.

Они вынесены на видеокарту Kaggle и выполняются там **один раз**:

```bash
make kaggle       # собирает dist/ru-fin-retrieval.zip, 20 МБ
```

Дальше по [kaggle/README.md](kaggle/README.md) — инструкция пошаговая,
до кнопок. Ноутбуки: [этап A](notebooks/kaggle_phase_a.ipynb) (запросы
и эмбеддинги), [этап B](notebooks/kaggle_phase_b.ipynb) (выдачи всех
конфигураций). Обратно едут не матрицы, а списки идентификаторов —
сотни килобайт вместо гигабайта.

**На маке остаётся всё, что памяти не требует:** сбор корпуса, нарезка,
метрики, доверительные интервалы, разбор ошибок. И замеры задержки —
их снимают именно здесь, потому что пользователь работает не на T4;
в отчёте указано, на каком железе снят каждый замер.

Побочный выигрыш: BM25 переписан на разреженную матрицу вместо `rank_bm25`,
и индекс по 61 922 фрагментам занял 52 МБ вместо двух-трёх гигабайт,
строится 8 секунд, отвечает за 1 мс. Совпадение формулы с `rank_bm25`
проверяется прогоном `make check-bm25` — расхождение 1,4e-06.

## Устройство

```
src/rufin/
  http.py              вежливый клиент: последовательно, с паузой
  pdftext.py           извлечение текста и оценка пригодности слоя
  vestnik_split.py     нарезка выпуска «Вестника» на отдельные акты
  chunking.py          нарезка актов на фрагменты: по структуре и по длине
  chunk_configs.py     конфигурации нарезки для абляций
  queryfilter.py       отбраковка негодных вопросов
  metrics.py           метрики и доверительные интервалы
  benchmark.py         формат MTEB: корпус, запросы, разметка
  retrieval/
    text.py            токенизация и нормализация запроса
    bm25.py            базовая линия на разреженной матрице
    dense.py           плотный поиск и FAISS
    model_specs.py     эмбеддеры и их префиксы
    hybrid.py          объединение выдач через RRF
    rerank.py          кросс-энкодер на первых 50
scripts/               воспроизводимые шаги, каждый пишет сырой вывод
kaggle/                тяжёлые шаги для чужой видеокарты
notebooks/             ноутбуки Kaggle: этап A и этап B
docs/raw/              сырой вывод прогонов: все числа в отчётах взяты отсюда
```

Сырые выгрузки сайтов в репозитории не хранятся — только скрипт сбора
и перечни документов.
