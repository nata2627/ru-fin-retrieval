# Запуск на Kaggle

## Главное правило. Никакого HuggingFace

**Все веса берутся с Kaggle Models, подключением входом. HuggingFace
не вызывается никогда и ни для чего.**

Причина не в предпочтениях. Секрет с токеном через API не прицепить вовсе,
ядро его не увидит, и каждое обращение к хабу идёт неавторизованным.
Такое обращение не падает, а **молча встаёт**, и будильник его не снимает.
Два прогона по двенадцать часов простояли ровно так. Это и есть главная
статья расхода квоты за 2-4 октября.

Как это обеспечивается в коде.

1. Переменные `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`,
   `HF_DATASETS_OFFLINE=1` ставятся **до первого импорта** transformers.
   Тогда случайное обращение к хабу падает сразу, а не висит.
2. Путь к весам разрешается только среди подключённых входов. Отката
   на имя модели в хабе нет, отсутствие модели это отказ, а не тихая
   загрузка.
3. Ничего не грузится по имени вида `владелец/модель`. Только путь
   в `/kaggle/input`.

Перед запуском проверить, что нужная модель есть на Kaggle Models.

```
kaggle models list -s "<имя>"
kaggle models instances list <владелец>/<слаг>
```

В метаданных ядра модель указывается как
`<владелец>/<слаг>/<каркас>/<вариант>/<версия>`, монтируется в
`/kaggle/input/models/<владелец>/<слаг>/<каркас>/<вариант>/<версия>`.

Зеркало это чужая копия. Сверять с уже посчитанным результатом, а не
принимать на веру.

## Два факта, незнание которых стоило 24 часов квоты

Клиент Kaggle **умеет показывать лог идущей сессии и остаток квоты**.
Утверждать обратное нельзя, это ложь, проверенная дорого.

| команда | что делает |
|---|---|
| `kaggle kernels logs -f <владелец>/<ядро>` | показывает лог идущей сессии вживую, как `tail -f` |
| `kaggle quota` | печатает израсходованное, остаток и дату обновления |

Вывод `kaggle quota` выглядит так.

```
resource  used    remaining  total   refreshAt
GPU       24.43h  5.57h      30.00h  2026-10-10T00:00:00
```

## Правила, без исключений

1. **Перед запуском назвать цену и остаток.** Сначала `kaggle quota`,
   потом оценка длительности, и только потом запуск. Запуск без этих
   двух чисел не делается.
2. **Во время прогона докладывать живые числа**, прочитанные через
   `logs -f`, а не слово «идёт». Молчащий прогон неотличим от вставшего,
   и это неотличие уже стоило двух сессий по двенадцать часов.
3. **Остановить ядро из клиента нельзя**, команды отмены нет, есть только
   удаление ядра целиком. Значит прервать может только человек в браузере,
   и он должен знать, что происходит. Сказать ему об этом до запуска.
4. **Прогон, который нельзя наблюдать, должен быть дешёвым.** Если
   наблюдения нет, длительность не больше получаса.
5. **Объём назначается по замеру, а не по арифметике.** Замер идёт
   на объёме рабочей пачки и тем же кодом. Арифметика на этом проекте
   ошибалась вчетверо.
6. **Результат пишется по частям.** Сессия ограничена по времени, и
   прогон, который пишет только в конце, при обрыве не оставляет ничего.
   Новый прогон обязан продолжать с места обрыва.
7. **Не запускать длинный прогон, когда человека нет.** Разрешение
   запускать не равно разрешению израсходовать недельную квоту без
   возможности вмешаться.

## Грабли окружения, уже найденные

* Датасеты монтируются то как `/kaggle/input/<слаг>/`, то как
  `/kaggle/input/datasets/<кто>/<слаг>/`. Пути не задавать, искать обходом
  по дереву.
* Модели входом монтируются как
  `/kaggle/input/models/<кто>/<модель>/<каркас>/<вариант>/<версия>`.
* `transformers` 5 переименовал `torch_dtype` в `dtype`. Разбором подписи
  это не определить, у `from_pretrained` в подписи только `**kwargs`.
  Выбирать по версии и проверять точность на самой модели.
* `DataParallel` на узле T4 x2 вставал на первой же партии. Считать
  на одной карте.
* Загрузка модели через `sentence-transformers` дважды уводила прогон
  в зависание на двенадцать часов, молча. Грузить через `transformers`
  напрямую.
* Зеркало модели с Kaggle Models сверять с уже посчитанным результатом,
  а не принимать на веру.
* **Библиотека обучения сама включает `DataParallel`**, как только видит
  две карты, и пишет об этом строкой «Currently using DataParallel (DP)».
  На T4 x2 это приводит к нехватке памяти. Прятать вторую карту
  переменной `CUDA_VISIBLE_DEVICES=0`.
* `warmup_ratio` в transformers 5 помечен устаревшим, доля разогрева
  задаётся через `warmup_steps` дробным числом. Выбрасывать неизвестный
  ключ нельзя: обучение пойдёт без разогрева и не скажет об этом.
* Зеркало e5-small несёт токенизатор, у которого служебные токены
  расходятся с настройками модели. transformers правит настройки под
  токенизатор и печатает об этом. На пулинг по маске это не влияет,
  но знать стоит.
